🛡 PingTool — OS Command Injection Demo

Assignment 3 • Variant: In-band Command Injection • C++ backend
🔴 Vulnerable Ping Tool UNSAFE
Root cause — C++ code: 
// ping_vuln.cpp
std::string host = argv[1];               // raw user input
std::string cmd  = "ping -c 3 " + host;  // concatenated into shell string
system(cmd.c_str());                       // ❌ shell interprets everything!

// Payload:  127.0.0.1; whoami
// Shell sees:  ping -c 3 127.0.0.1; whoami
//              ↑ normal ping          ↑ injected command runs too!
🟢 Secure Ping Tool MITIGATED
Mitigation applied — C++ code: 
// ping_safe.cpp  —  two layers of defence

// ✅ Layer 1: allow-list validation
std::regex allow_list("^[a-zA-Z0-9.\\-]+$");
if (!std::regex_match(host, allow_list)) {
    return 1;   // reject — shell metacharacters blocked
}

// ✅ Layer 2: execvp() — argument vector, NO shell
char* args[] = { "ping", "-c", "3", host.c_str(), nullptr };
execvp("ping", args);   // OS passes args as DATA, not a shell string
📚 Other Mitigations (Theory)

1. Avoid the shell entirely
Use native OS or library APIs instead of shell commands altogether. If there is no shell, there is no injection surface. In C++ for example, use raw ICMP sockets instead of calling ping.


2. Parameterised execution / argument vector
Pass each argument as a separate element to execvp() (C++) or subprocess.run(list, shell=False) (Python). The OS hands each element directly to the program as data — shell metacharacters lose all meaning.


3. Allow-list validation
Whitelist only the exact characters a valid hostname or IP needs (^[a-zA-Z0-9.\-]+$). Reject everything else before it reaches any execution path.


4. Least privilege
Run the web server process under a restricted OS account with minimal permissions. Even if injection somehow succeeds, the attacker can only do what that account is allowed to do — dramatically limiting blast radius.
